# leadsgen 线索流水线 v1

状态：产品边界与验收基线。第一阶段的角色隔离、sales 来信导入、指派/接手、个人跟进状态和 Aimail 单线程授权已在未合并开发分支实现并通过测试；尚未发布或生产验收。重复企业的人工合并界面、内外通知和真实员工验收仍未完成。

## CRM 边界

CRM 是客户关系管理（Customer Relationship Management）：集中管理潜在及现有客户的资料、互动记录和关系进展。企业档案、联系人、邮件互动和销售跟进阶段一旦在同一平台持续维护，就已经是 CRM 能力；是否称为 CRM 不由报价或合同模块决定。

本项目实施一个聚焦获客的轻量 CRM：发现企业、核验联系人、记录来源、整理客户回复、分配负责人并跟踪下一步。它不做完整客户生命周期管理，也不做正式客户主数据、报价、订单、合同、售后、收入预测或佣金。已有 leadsgen 是线索来源和采集工作台；它需要演进成获客与初步销售跟进平台，而不是再建一套完整 CRM。

## 系统职责

- **leadsgen** 是企业/潜在线索档案、来源证据、初筛、合并、分配、pipeline 状态和统计的权威记录。
- **Aimail** 是邮件原文、附件、AI 阅读结果、SMTP/IMAP 事实、邮件线程及个人发件身份的权威记录。
- 两边通过不可变的 `lead_id`、`company_id`、Aimail `prospect_id` / `thread_id` 与事件 ID 关联；不能复制邮件正文作为另一份事实来源。
- `sales@glocalstorage.com` 是公共收件来源，不是员工身份或发件身份。它的收件权限按需给线索管理员；分配员工只获得相关线程及附件权限。员工通过自己的个人发件身份联系客户。

## 两种入口，一条分流

1. **主动发现**：leadsgen 发现公开企业、业务联系方式及出处，进入「待初筛」。初筛员核实重复项、业务匹配、联系地址和来源；只有通过人工发送资格核对的记录才成为「待联系」。邮件草稿及发送由 Aimail 管理，每次真实外发仍须遵守已批准的人工审核策略。收到回复后以原始邮件线程关联同一线索；无回复、退信、退订各自记录，不把等待回复直接升级为销售机会。
2. **sales 收件询盘**：Aimail 保留原始来信并产生待初筛事项；leadsgen 建立/匹配企业和线索，记录来源为 `sales_inbound`，关联 Aimail 线程。确认是有效询盘后直接进入「待分配」，不经过主动开发阶段。
3. **合并与归属**：按规范化域名、企业名和联系人邮箱提示重复；合并必须由有权限的人确认，并保留来源、字段证据、邮件线程和操作审计。一个企业可以有多条不同需求线索，但同一条需求不得因主动发现和来信产生两条互不相关的记录。
4. **交接给销售**：线索管理员选择一个已验证员工并提交交接；员工收到只含必要信息和受认证链接的内部通知，在 leadsgen 中接受或退回。接受后负责人唯一，线索进入员工「我的跟进」。通知本身不附客户正文或附件。
5. **员工跟进**：员工看到分给自己的企业摘要、已核验联系人、必要来源证据、AI 摘要（明确标注推断和引用）、相关邮件/附件与下一步日期。回复从 Aimail 以员工个人邮箱发出；来信、AI 建议和状态变更不能自动代替员工确认。

## MVP 阶段

用少量可执行状态覆盖业务，而不把不同事实压进一个状态字段：

| 维度 | 状态 |
| --- | --- |
| 初筛 | `待初筛`、`待补信息`、`可联系`、`不合适`、`重复` |
| 主动联系（仅主动发现入口） | `未联系`、`待人工审核`、`已发送/等待回复`、`已回复`、`退信`、`已退订` |
| 分配 | `未分配`、`待接手`、`已接受` |
| 员工跟进 | `待联系`、`跟进中`、`等待客户`、`等待内部`、`稍后跟进`、`结束` |

阶段互相独立：邮件 SMTP 已接受不表示客户已读或线索合格；AI 判断不表示人工初筛通过；交接已发送不表示员工已接受。`结束` 必须记录原因（无需求、联系无效、客户拒绝、重复、转入后续系统等）；不增加报价、合同或赢单流程。

## 权限

| 角色 | 可见与可做 |
| --- | --- |
| 线索管理员 / 初筛员 | 全部采集任务与待初筛、重复核对、来源和统计；建档、人工核验、交接、撤回和审计。初始授权由企业身份映射明确指定，不能仅凭“已登录”授予。 |
| 跟进员工 | 仅查看分给本人或待本人接受的线索；接受/退回、更新本人跟进阶段和下一步、查看被授权的邮件线程/附件。不能查看原始全量采集池、其他员工名单或未分给自己的客户。 |
| 系统集成身份 | leadsgen→Aimail 只可导入必要线索、幂等回执和同步邮件状态；无浏览器登录、分配权或发件权。 |

服务端必须在列表、详情、附件、导出、搜索、统计、状态变更和关联邮件接口逐一执行权限过滤；只隐藏前端导航不算访问控制。接手、退回、改负责人和阶段变化记录 actor、时间、旧值、新值和原因。管理员可以撤销授权。

## 统计

第一版只统计可审计数量：按来源、地区、阶段、负责人汇总企业数/线索数；待初筛、待分配、待接手、已接受、等待回复和超期未更新数量；主动联系数、实际回复数、有效询盘数及退信/退订数。展示时间范围与分母。公司数与线索数分开；邮件尝试与 SMTP 接受分开；不显示未经校准的收入、成交概率或预测金额。

## 第一阶段验收

- 未授权已登录员工无法通过页面、API、搜索、导出或改写接口看到全局名单或其他员工记录。
- Larry/指定初筛员可以分别处理主动发现线索和 sales 来信，保留每个字段的公开来源或邮件来源。
- 同一企业的主动发现与来信可合并至一个档案，同时保留两个来源和所有线程；错误合并可以审计并人工纠正。
- 管理员交接后只有指定员工可见；接受后负责人唯一，管理员可见；员工通知链接要求登录且只打开授权记录。
- 回复内容、附件与发件身份仍由 Aimail 管理；leadsgen 的统计和状态从真实事件更新，不能把导入回执或 SMTP 接受显示成客户已回复。
- 没有任何未明确授权的客户邮件被自动发送；退订和抑制状态在再次采集/导入时仍有效。
- 代码、自动化测试、生产部署和员工真实业务验收分别记录，不互相替代。

## 当前实现记录

- 可信 OIDC 邮箱决定 leadsgen 管理员/销售角色；未列入名单的登录账号拒绝访问。管理员读取全量采集池和待初筛线索；员工只能读取发给自己待接手或已接手的记录。
- Aimail 仅向 leadsgen 提供在 `sales@glocalstorage.com` 上由人工确认的线索事实。导入按 Aimail 线索 ID 幂等，不把邮件正文或附件复制到 leadsgen，也不会把来信放进主动开发发送队列。
- 员工接受来信线索后，leadsgen 才向 Aimail 请求该线程的访问权。Aimail 校验集成令牌、跟进员工名单和线程所属共享邮箱；员工的共享邮箱列表保持不可见，访问仅限授权线程及其邮件附件。权限同步失败会安全退避重试，并在管理员视图显示状态。
- 重新分配通过相同 leadsgen 线索 ID 更新 Aimail 线程负责人并写审计事件；不同来源或已有独立交接状态的线程不会被静默覆盖。
- 当前本地验证：Aimail 后端测试全过；leadsgen 25 项测试通过、1 项既有测试跳过，ruff 全过；前端 TypeScript 检查和生产构建通过；infra leads OIDC/Caddy 信任边界 4 项检查通过。
- 尚未合并/部署。生产配置、运行镜像、线上登录权限和 Larry/Isaac 的完整业务场景尚未据此验收；没有发送客户邮件。
