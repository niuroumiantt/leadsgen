# 目标市场发现计划

本批在已上线的采集工作台、企业档案与客户时间线上增加搜索来源。
生产版本、真实搜索服务和首轮执行结果以
[发布检查点](https://github.com/niuroumiantt/infra/blob/main/docs/handoff/leadsgen-discovery-release-2026-10-02.md) 为准。
代码支持 Brave / Tavily，不代表服务器已有可用凭据或额度。

## 使用路径

1. 管理员打开 **发现计划 → 新建发现计划**，选择国家、客户类型、产品、筛选目标和搜索词。
   提供 GPU 云/数据中心、服务器配件渠道、企业 IT 集成商三个可编辑模板。
2. 保存后保持暂停。**搜索一次**会创建一轮独立记录，保存当时的完整计划和查询词。
3. **执行记录 → 查看搜索过程与结果**查看请求时间、成功/失败原因、结果出处、重复来源和人工排除依据。
4. 打开来源核验独立公司官网。选中最多 30 个，**转入官网采集**进入原有队列；可跳到逐页采集过程。
   来源是搜索建议，国家、行业和初始分层是计划标签，不能直接当作已核实的公司事实。
5. 找到公开业务邮箱并建档后，可直接 **查看客户**，沿用原来的企业编号、负责人、时间线和阶段。
   没找到邮箱、robots 拒绝、超时等仍显示真实采集结果，不填造联系信息。
6. 质量符合目标后启用定时；暂停会停止后续请求，已经在途的响应会保留为排除记录。

发现计划仅管理员可见、可操作。销售继续只看本人已分配/待接手的客户和邮件。
网页文本只显示为文本，不执行搜索摘要中的代码或指令；不使用摘要自动确认采购需求。

## 什么在增长，什么没有变化

搜索结果 → 待核验官网 → 转入采集 → 已建档 → 确认需求及以后，分别统计。
前几项是来源数，后两项是本轮转入采集后关联的独立账户数，重复来源不重复贡献客户数。
这里的账户仍是来源/机会，企业确认与关联沿用既有 `company_id` 规则，不按名称强行合并。

官网按注册域名去重（沿用现有 Public Suffix 规则），跨计划、跨批次共用登记表。
重复结果保留搜索出处，能追溯首次搜索及其处理结果；后续被核验入队后也能看到采集入口。
原有客户或手动采集名单再次出现不自动重采；原来的失败重试仍在采集工作台单独处理。
人工排除的首条结果继续参与去重。误排除时先核实依据，当前可使用原有手动官网任务入口，
不会自动清空历史排除或把旧结果改成“新发现”。

**本批不发送邮件，也不自动提交开发信名单、创建发信序列或改变邮件状态。**
公开邮箱只是联系入口。后续业务阶段为待核验、可联系潜客、已首次联系、已建立沟通、
已确认需求、已报价、商务/技术推进、成交/转交履约，以及关闭/长期培育。
具体阶段、必填资料、唯一标识和追加历史规则见 [客户进展说明](customer-progress-2026-10-02.md)。

## 频率、请求上限和故障行为

- 可选仅手动、每 6 小时、每天、每周。启用定时后的第一轮立即到期；此后按本轮调度时间计算间隔。
  修改已启用计划会从修改时间重新安排下一轮，正在执行的记录保持原目标快照。
- 每轮 1–5 个查询，每个查询最多 10 个结果。每条词附加目标国家英文名；Brave 同时传国家参数。
  地理搜索只是线索筛选条件，需要核实企业实际所在国家。
- 全部计划、两种服务共用每日请求上限，默认 **20 次**，按 UTC 00:00 重置；界面显示本地重置时间。
  上限是应用发出的请求次数，不是服务商费用承诺。Tavily 使用 basic 搜索，不获取原始正文或 AI 答案。
- 请求先原子登记再执行 HTTP；超时/失败也计入应用额度，不能据此推断服务商实际计费。
  每条查询最多请求一次；每轮查询之间至少等待 1 秒，空闲队列每 5 秒检查。
- 同计划最多一轮等待/运行；手动请求有幂等 ID；多次暂停/编辑使用版本防止旧页面覆盖。
- 停机错过的多个周期只补一轮。重启后已在途的查询标记中断，不自动重放；未启动的队列可继续。
- 无有效配置不允许启动或启用计划；运行时配置失效/认证错误会暂停计划。
  暂时失败按 15、30 分钟退避，连续三次失败暂停；达到每日上限延期到下个 UTC 日，不计连续失败。
- 搜索错误保留安全的类别，不把响应正文、请求头或凭据写进审计/前端。
  搜索返回最大 512 KB、20 秒网络超时、不跟随重定向，固定使用官方 API 地址。
- 搜索 URL 过滤内网/IP/非 HTTP 地址与常见目录/社交站。转入官网采集后仍执行原有公开 DNS、
  固定连接、robots、同源、请求间隔和大小限制，搜索结果不会豁免这些检查。
- 使用单个应用实例。独立搜索、官网采集和邮箱集成线程共用短事务 SQLite 连接。
  多开应用进程不是受支持的扩容方式。

## 配置与增量迁移

由 M5 在已有服务器私有环境文件中配置，密钥不进入 Git、浏览器、命令参数或聊天。
不要打印整个 env、容器完整 inspect 或第三方响应正文；只记录存在性和经过脱敏的验证结果。

| 环境变量 | 行为 |
| --- | --- |
| `LEADSGEN_BRAVE_API_KEY` | 已有 Brave Web Search 凭据，缺省未配置 |
| `LEADSGEN_TAVILY_API_KEY` | 已有 Tavily 凭据，缺省未配置 |
| `LEADSGEN_SEARCH_DAILY_LIMIT` | 默认 20，允许 1–200；本批部署保持 20 |

无需改变 Authentik、Aimail、邮箱配置、通知账本或同步游标。无新增生产依赖。
新增 `discovery_plan`、`discovery_run`、`discovery_query`、`discovery_result`、`discovery_site` 五张表。
迁移仅从已有候选建立官网登记，不自动创建计划、搜索、重试或通知。重复迁移保持既有业务表内容。
搜索结果出处列有拒绝修改/删除的触发器；审核结论单独可变，动作记审计。运行配置是创建时快照。
回退旧镜像前先停止发现计划并保留新表及当期数据库，不能用旧备份覆盖升级后的真实业务。

## 接口与检查

所有 `/api/discovery` 接口要求现有管理员身份，写入仍要求现有同源/客户端头。

| 接口 | 作用 |
| --- | --- |
| GET `/api/discovery` | 计划、服务配置存在性、每日额度和待核验数 |
| POST `/api/discovery/plans` | 保存暂停的新计划 |
| POST `/api/discovery/plans/{id}` | 带 version 编辑目标与频率 |
| POST `/api/discovery/plans/{id}/schedule` | 带 version 启用/暂停 |
| POST `/api/discovery/plans/{id}/runs` | 带 version + UUID request_id 请求一轮 |
| GET `/api/discovery/plans/{id}/runs?before=` | 每页 20 轮，时间游标 |
| GET `/api/discovery/runs/{id}` | 快照、逐条查询、来源与动态采集/客户关联 |
| POST `/api/discovery/review` | 最多 30 个来源转采集或带原因排除；批次冲突整体拒绝 |

回归包括并发调度和额度、重启中断、暂停时迟到响应、跨批去重、重复审核、来源保护、
旧表迁移、权限/CSRF、搜索服务 HTTP 合同与异常响应。浏览器使用临时数据库和模拟搜索服务，
走通计划创建、搜索、审核、采集/客户入口、并发编辑与 1440/390px 布局，不消耗真实搜索额度。
真实 Brave/Tavily 网络、生产配置和采集效果须由 M5 单独验收。
